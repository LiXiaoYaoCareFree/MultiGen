# 整合总结报告：数据构建、ResearchArena复现与迭代验证

## 一、精简的数据构建过程

SciEval-Bench 的构建遵循五阶段流水线，可在8周内完成1200条评估实例的完整数据集。

**第一周：原始论文采集。** 预览167个关键词覆盖全部六大学科（`--dry-run`），小批量测试API连通性（每关键词2篇，约330篇），正式批量采集（每关键词10篇，目标2000-3000条）。工具为`scieval_collector.py`，数据源为arXiv和Semantic Scholar双API。

**第二周：论文筛选与预处理。** 去重（基于arXiv ID，预期重复率5-15%），全文可获取性过滤（保留有arXiv ID的论文），时间窗口过滤（2022年+，紧缺学科放宽至2020年），筛选后保留1500-1800条。

**第三至六周：结构化标注。** 随机选取1200条，LLM辅助生成初始标注（学科四层级路径、任务类型、难度级别、五维元数据），人工交叉标注（两名标注者盲法独立标注，Kappa<0.7触发仲裁），Code-Aware实例生成编造检测清单（5-15条可验证声明）。

**第六至八周：三级质控。** 第一级自动格式验证（零错误目标），第二级去污染与一致性校验（8模型截止日期比对），第三级难度与多样性平衡检查（L1:L2:L3=40:35:25 + 六任务全覆盖 + 六学科全覆盖 + Code-Aware≥25%，目标≥85/100）。

**第八周：发布打包。** 语义化版本控制（v1.0.0），生成含README/CHANGELOG/LICENSE/MANIFEST的完整发布包，SHA256校验。

## 二、ResearchArena复现分析与优化点

### 2.1 架构与数据构建

Research Arena 的核心是一个状态机驱动的三阶段流水线，每阶段由CLI Agent（Claude Code/Codex/Kimi Code）自主执行：IDEATION→SELF_REVIEW_IDEA→EXPERIMENTS→SELF_REVIEW_EXPERIMENT→PAPER→SELF_REVIEW_PAPER→REVIEW→ACCEPTED/FAILED。

种子体系定义了85个研究种子（远超论文报告的13个），每个种子包含name/conferences/platform/domain四个字段，覆盖ML、系统、数据库、编程语言、理论CS和安全六大领域。论文实验选择了5个CPU+8个GPU代表性种子，每个种子由3种Agent各运行3次，共117篇论文。

### 2.2 双层评审机制

Stanford Agentic Review（SAR）仅基于论文PDF评分（0-10分ICLR量表），Peer Review with Artifact Inspection（PR）同时检查代码和实验产出（九维度评分）。SAR与PR之间的系统性差距（0.5-1.0分）是评估体系设计的核心实证依据——仅看论文表面会高估AI科研能力。

### 2.3 五个未解决的关键问题

**引用幻觉（36-72%虚假引用率）：** LLM倾向"流畅的虚构"——搜索不到理想引用时编造"应该存在"的论文。评审者被要求验证引用但无自动化验证管线。**实验逻辑不完整：** Agent的三个阶段产物常不一致——声称的消融实验未实现、方法描述与代码不符、论文数字与实验结果不匹配。Agent倾向"修复论文"而非"修复实验"。**自评审偏差：** 同一Agent类型评审自己产出的自确认偏差——Claude Code自评审idea改进率100%但外部评审揭示严重缺陷。**缺乏系统化编造检测：** SAR完全不检查代码，PR的代码检查是评审者"自由裁量"而非结构化流程。**资源-质量瓶颈：** H100扩展实验证明更强GPU不带来更好质量——瓶颈在实验设计能力而非计算资源。

### 2.4 优化方案

**引用验证自动化：** 在PAPER和REVIEW之间插入`citation_verify`步骤，通过CrossRef+Semantic Scholar API批量验证每条引用。**引用策略改为"检索→引用"：** 论文只能引用`retrieved_refs.json`中记录的检索结果，从源头杜绝引用编造。**引入独立多模型评审面板：** 自评审使用不同于研究Agent的LLM类型。**实验-论文一致性自动校验：** 正则提取论文数值声明→与results.json自动比对→超出容差标记为不一致。**结构化编造检测清单：** 借鉴SciEval-Bench设计，自动生成可验证声明清单并逐项核对。

## 三、迭代生成验证结论

### 3.1 原型设计

针对引用幻觉和实验逻辑不完整两个核心问题，设计了迭代式自评审生成原型。流程为：Round 0基线生成→评审器检测问题→反馈→模型修订→Round 1-3迭代。仿真参数基于Research Arena报告的三种Agent真实行为数据：Claude（36%虚假引用率，26%实验缺失率，修订效率0.7）、Codex（8%虚假引用率，3%实验缺失率，修订效率0.9）、Kimi（72%虚假引用率，77%实验缺失率，修订效率0.3）。

### 3.2 迭代效果

**对引用幻觉的中等缓解效果。** Claude从62%→70%（+12%），与Research Arena基线64%相比有改善但未根除。Codex基线已很高（92-93%），迭代空间有限。Kimi从28%→38%（+10%），有改善但仍有60%+虚假引用——**迭代循环无法解决"系统性编造引用"的根本问题**。关键瓶颈在于：修改效率受限于`citation_modification_rate`（0.3-0.5），Agent在修订时可能用新虚假引用替代被发现的旧虚假引用（治标不治本），评审器检测准确率70%意味着30%的虚假引用始终未被发现。

**对实验逻辑不完整的效果不稳定。** 实验完整性在迭代中波动——Round 2可能修复至100%，Round 3又退步至60-80%。原因在于：Agent在修订时可能引入新的缺失（修改论文描述而非补充实验），自评审无法检测所有实验缺失（30%遗漏率），实验缺失的修复比引用替换更困难（需要实际编写代码而非仅修改文本）。

**边际收益递减。** Round 0→1改善最大（+10%引用准确率），Round 1→2和2→3改善递减（+2-3%）。Codex在两种子上Round 2就提前结束（所有问题已解决）。Kimi在Round 3仍有大量问题，迭代循环对其效果最差——系统性编造问题无法通过迭代解决。

### 3.3 最终结论

迭代式自评审生成对引用幻觉有中等缓解效果（+10-12%），对实验逻辑不完整效果不稳定。它**不能替代**系统性的编造检测机制——必须结合以下措施才能根本解决Research Arena发现的问题：引用"检索→引用"策略从源头杜绝编造、实验-论文自动化一致性校验缩小学术文本与代码产出的差距、独立多模型评审面板打破自确认偏差、结构化编造检测清单实现逐项核对。迭代循环的定位应是"辅助性自我改进"而非"替代性质量保障"。
